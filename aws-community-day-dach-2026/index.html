Honest architecture

Not Lambda. Not a chatbot-only bot.

  • Telegram — where I talk to the agent (phone, anywhere)
  • Hostinger VPS — OpenClaw in Docker, ~€10/mo, always on
  • Watches GitHub issues, plans, codes, opens PRs
  • AWS — where production lives (HalloCasa, ai-secure, qr-plakat)
  • Human in the loop: review PR, SSO approve, kill runaway jobs

I considered serverless. VPS won for persistent state, heartbeats, Cursor CLI, and Telegram UX.

Design principle

Human in the loop — always

  • Agents execute — plan, code, test, open PR
  • Humans decide — review diff, approve merge, kill runaway jobs
  • Full autonomy sounds cool · production needs guardrails
  • Air Canada & HDI: AI assists · people stay accountable

Autonomous pipeline ≠ autonomous production. The factory runs 24/7 — you still own the merge button.

Why VPS, not Lambda?

I tried the serverless story — kept the VPS

VPS wins

Persistent shell · Cursor CLI · no 15 min cap · Telegram always on

Serverless pain

State across invocations · cold starts · Step Functions for long runs

AWS still central

Production targets · SSO · pipelines · MCP endpoints

Caveat

LLM tokens dwarf infra either way (~95%)

Takeaways

When this pattern works

✓ Do

  • VPS control plane + AWS production targets
  • Telegram/Slack UX + GitHub PR workflow
  • Human merge gates + SSO approval for AWS
  • Separate agent infra from what you deploy

✗ Don't

  • Claim serverless when you run a VPS
  • Auto-merge / auto-deploy without review
  • Force Lambda for long Cursor CLI sessions
