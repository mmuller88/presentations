Serverless AI Factory

Not a chatbot. A dev pipeline.

  • Watches GitHub issues — not Telegram, not email
  • Plans the work, writes code, opens pull requests
  • Runs on scale-to-zero AWS — agents on demand
  • Production for months · agents draft work overnight — humans ship it
  • Human in the loop: review PR, approve merge, set spend limits

Different talk: OpenClaw VPS → serverless migration (personal agent, heartbeats, Telegram).

aws-community-day.de · 15 Sep 2026 · Kosmos Berlin

Design principle

Human in the loop — always

  • Agents execute — plan, code, test, open PR
  • Humans decide — review diff, approve merge, kill runaway jobs
  • Full autonomy sounds cool · production needs guardrails
  • Air Canada & HDI: AI assists · people stay accountable

Autonomous pipeline ≠ autonomous production. The factory runs 24/7 — you still own the merge button.

Takeaways

When to build a Serverless AI Factory

✓ Do

  • Bursty, async workloads
  • Issue-driven automation with human merge gates
  • Burst economics over idle servers
  • Human in the loop — review, approve, kill runs

✗ Don't

  • Auto-merge without human review
  • “Fully autonomous” with no spend guardrails
  • Persistent WebSockets / sub-second latency
